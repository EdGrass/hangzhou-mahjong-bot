# 参赛程序说明（可直接粘贴到申报页面正文）

**完整可运行源码仓库：** https://github.com/EdGrass/hangzhou-mahjong-bot

---

## 一、程序是什么

杭州麻将竞技平台的**全自动对局程序**（Python 3.12）：以“向听数 + 真进张（live ukeire）”
驱动的速度型引擎为核心，配套 A/B 评测台、复盘审计与延迟基准工具链；部分策略在规则引擎之上叠加**训练好的小型网络**
（弃牌排序 / 副露门控 / 爆头可达性价值）。

- **全程 AI 自动决策，无任何人工干预**：报名 → 到位 → 开赛 → 逐手决策 → 阶段切换 → 终态退出；
- 决策只使用**服务器公开状态 + 自己手牌**，不读取任何对手私有信息；
- 每一步（摸牌弃牌 / 碰 / 吃 / 杠 / 胡 / 过）均由程序自行判断并提交，断线/超时由程序自身重试恢复。

## 二、运行环境与依赖

| 项 | 要求 |
|---|---|
| Python | **3.12**（实测 3.12.10；Windows / Linux 均可） |
| 必需依赖 | `numpy`、`torch`、`psutil`（见 `requirements.txt`） |
| 可选依赖 | `fastapi` + `uvicorn`（仅本地自对弈看板，**参赛不需要**） |
| 模型权重 | **4 个小型权重随仓库提交**（`var/c073_orig_w2_net.pt`、`var/c121_meld_net.pt`、`var/c089_ranker_net.pt`、`var/baotou_v1.pt`，合计 ~0.8MB） |
| 硬件 | 普通 PC 即可（无 GPU、无数据库、无外部服务） |

```bash
pip install -r requirements.txt
```

说明：**纯规则策略**（如 `speedvalue` / `speedc151` / `speedvalueplain`）**只用标准库**，不装任何包也能跑；
而**带学习网络的策略**需要上表依赖与对应权重（例：爆头可达性 V 需 `torch` + `baotou_v1.pt`；副露/排序需 `numpy` + 对应 `.pt`）。
权重文件缺失时相关策略会自动回退到纯规则基线（不报错、不崩溃，只是变弱）。

## 三、如何接入官方平台

| 环节 | 实现 |
|---|---|
| 平台指南版本 | 已对齐服务器 **v35**（`GUIDE_VERSION_KNOWN=35`，2026-09-23 BREAKING 已修） |
| 平台地址 | `https://10.240.169.190:18080`（自签 TLS，程序内部已处理证书校验；亦可用 `--server` / `HM_SERVER` 覆盖） |
| 认证 | `Authorization: Bearer <参赛令牌>`（64 位十六进制）；报名令牌自动发现赛事，全局令牌需显式给 tournament id |
| 状态机 | `registering → running → stage_done → stage_open → running … → finished`；自动完成 **报名 / 到位(ready) / 阶段出席确认 / 淘汰退出** |
| 事件驱动 | 走 **notify 事件流（SSE）**长轮询；事件合并后按需取快照，不占 `/state` 频率配额 |
| 窗口应答 | 弃牌 3s、碰/吃 1s 窗口内提交；本机实测决策 **p99 ≈ 30–80ms**（随负载波动，远低于窗口） |
| 容错 | 429 / 5xx / 网络瞬断指数退避；**404 按 body 的 code 分流**：`TOURNAMENT_GONE`（房暂时不可达）⇒ **不限时重试**，`TOURNAMENT_NOT_FOUND`（房不存在）⇒ **立即放弃**，其它/无法解析 ⇒ 保守重试；窗口 409 竞态自动恢复 |

## 四、如何启动

### 1) 免认证自检（推荐第一步，不需令牌）
```bash
python -X utf8 run_bot.py --smoke --server https://10.240.169.190:18080
```

### 2) 参赛（最小命令）
```bash
python -X utf8 run_bot.py <参赛令牌> --server https://10.240.169.190:18080
```

### 3) 指定策略
```bash
python -X utf8 run_bot.py <参赛令牌> --server <URL> --strategy speedvalue
```
> **`--strategy` 的取值以 `var/_keeper_strategy.txt` 为准**（本项目按逐役预登记实验择优；
> 上面的 `speedvalue` 只是**示例**，10/7 定臂后生产策略名以该文件为准）。
（全部可用策略见 `python -X utf8 run_bot.py --help`）

### 4) 无人值守运行（正式赛推荐）
```bash
python -X utf8 tools/keep_alive.py <参赛令牌> --strategy speedvalue --server <URL>
```

### 5) 开赛前一键体检
```bash
python -X utf8 tools/preflight.py --server <URL>       # 输出 READY / NOT READY（退出码 0/1）
```

## 五、稳定性设计

- 事件用 **notify SSE** 驱动并做事件合并，避免并发下的限速风暴；
- 429 / 网络瞬断 / 5xx 指数退避；窗口 409 竞态自动恢复；
- **404 分流（v35 后）**：`TOURNAMENT_GONE`（服务器约每 70 分钟重启一次会产生 502→404 风暴，房**暂时**不可达）⇒ **不限时重试、不再按“持续时间”判死**；`TOURNAMENT_NOT_FOUND`（房不存在）⇒ 立即退出；其它 code ⇒ 保守重试；（旧实现只看 404 持续 120s，曾把 29 次 GONE 误判成“房已删”）
- 决策延迟实测 **p99 ≈ 30–80ms**（窗口 1s / 3s，0 条超窗；随负载波动）；
- 长跑由 `tools/keep_alive.py` 看护，崩溃自动重启；报名 / 到位 / 确认均幂等，重启语义安全。

## 六、全自动决策声明

- 每一步均由程序自行决策并提交，**全程无人工干预**；
- 决策仅使用服务器公开状态与自身手牌，**不读取任何对手私有信息、不使用任何外部数据**；
- 断线 / 窗口错过 / 服务器重启等异常全部由程序自身重试与重建状态，不需要人工介入。
