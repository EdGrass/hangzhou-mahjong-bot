## 提交项 1：使用程序参赛说明

### 1. 程序概述

本项目是一套面向杭州麻将官方竞技平台的**全自动对局程序**，使用 Python 3.12 实现。程序根据服务器公开状态和自己手牌，自动完成报名、到位确认、阶段出席、逐手决策和赛后退出，全程不需要人工介入。

- 决策类型覆盖：摸牌、弃牌、碰、吃、杠、胡、过、窗口应答、阶段切换。
- 决策依据仅来自：服务器公开牌河/副露/状态 + 自己手牌 + 规则允许的可见信息。
- 不读取对手私有手牌，不注入外部数据，不依赖人工点击。
- 生产策略以 `var/_keeper_strategy.txt` 和 `var/.final_arm.txt` 为准；当前最终臂为 `speedvalue`。

### 2. 运行环境

| 项目 | 要求 |
|---|---|
| Python | 3.12（实测 3.12.10） |
| 操作系统 | Windows / Linux 均可 |
| 必需依赖 | `numpy`、`torch`、`psutil`，见 `requirements.txt` |
| 硬件 | 普通 PC 即可，无 GPU、无数据库、无外部服务依赖 |
| 模型权重 | 仓库内随源码提交小型权重文件，合计约 0.8MB；缺失时相关策略自动回退到规则基线 |

安装：

```bash
pip install -r requirements.txt
```

### 3. 如何接入官方平台

1. 参赛者先登录杭麻平台领取正式比赛令牌。
2. 程序使用该令牌调用官方平台 API，并自动发现/进入对应赛事。
3. 平台接口按服务器指南版本适配，状态机覆盖 `registering → running → stage_done → stage_open → running → finished`。
4. 赛前可先跑免令牌自检：

```bash
python -X utf8 run_bot.py --smoke --server <官方平台地址>
```

5. 正式参赛最小命令：

```bash
python -X utf8 run_bot.py <参赛令牌> --server <官方平台地址> --strategy speedvalue
```

6. 无人值守推荐命令：

```bash
python -X utf8 tools/keep_alive.py <参赛令牌> --server <官方平台地址> --strategy speedvalue
```

> 平台地址、令牌和赛事 id 以赛事通知/平台页面为准；仓库与本文档不包含任何个人令牌。

### 4. 自动决策与稳定性设计

- 通过平台事件流驱动状态推进，避免高频轮询触发限流。
- 弃牌 3 秒、碰/吃 1 秒窗口内提交；本机实测决策延迟远低于窗口限制。
- 对 429、5xx、网络瞬断使用指数退避重试。
- 对 404 根据服务端错误码分流处理：临时不可达时保守重试，确定房间不存在时立即退出。
- 窗口 409 竞态自动恢复；报名、到位、阶段确认均幂等，进程重启后语义安全。
- 长跑由看护进程监控，异常退出后自动拉起。

### 5. 合规声明

- 全程由程序自动决策和提交，无人工代打、无人工干预。
- 仅使用服务器公开状态和程序自身手牌。
- 不使用任何非公开数据、外部情报或对手私有信息。
- 提交材料中的令牌、cookie、平台内部鉴权信息均不写入源码仓库。

## 答辩材料：三个评分维度

### 1. 创新性：策略设计与 AI 运用方式

- 以杭麻规则为目标，构建“向听数 + 活进张 + 番型价值 + 牌效风险”的决策框架。
- 除规则策略外，项目搭建了行为克隆网络、特征评测、离线复现和在线 A/B 评测链路，用于把“直觉规则”转化为可验证的模型改进。
- 采用预登记实验、机制端点、强手房分层和熔断保护，避免只凭单局或小样本过拟合。
- 最终上线采用经过正式评测的稳定臂，保证创新探索不牺牲比赛稳定性。

### 2. 完整性：程序完成度、稳定性与工程质量

- 完整覆盖平台接入、令牌认证、赛事发现、报名、到位、对局决策、阶段推进、异常恢复和终态退出。
- 具备离线复盘、效果对比、延迟测试、冒烟自检、单元测试和最终就绪检查。
- 对网络异常、窗口竞态、服务器重启、进程退出等生产问题进行失败保护与自愈。
- 代码、模型、依赖、测试和运行文档均随仓库提交，可独立复现。

### 3. 业务价值：对麻将玩法设计的启发与可复用经验

- 展示了“规则引擎 + 小型模型 + 严格评测”的落地路径，适合推广到其他回合制策略游戏。
- A/B 实验、预登记判据、强手房分层和熔断机制可复用为通用 AI 竞技评测流程。
- 对麻将玩法的数值平衡、番型收益和行为风险提供了可量化的分析工具。
- 工程上的限流、幂等、断线恢复和无人值守方案可直接复用到其他平台型 Bot 项目。
