# 杭麻 Bot Agent 自迭代方案（双环门禁协议）

> 版本：2026-09-06 | 配套：docs/iter/{queue.md,journal.md,reports/} | Goal：goal-4b4c1d3e
> 适用对象：Agent（本会话主 Agent 与其子 Agent）与人工评审者共用的迭代规则书。

## 1. 项目判读结论（为什么要这套方案）

阅读代码与历史（git log + PROJECT.md + arena 数据 + logs/）后的三个核心事实：

1. **工程链完整、真机协议已稳定**：协议层（api/protocol/game/model/meldtrack）经历 10+
   个真机事故修复后进入稳态；本地引擎（hu/fan/shanten_exact/sim）有 132 项黄金集对齐；
   评估台（arena）与工具链（room_ctl/stability/preflight/replay_audit/keep_alive）齐备。
2. **真正的瓶颈不在工程而在"证据"**：策略演进史（A→B→E；F、G 已清理）反复证明——
   本地 Arena 优势**不能假设迁移到真机**：SpeedB 本地压 A +1.5/场、SpeedE 本地压
   A +4.5/场，但 SpeedE 与 SpeedF 真机同桌 408 局统计不可分（SE≈0.5/场）后收敛于 E。
   即：**真机同桌证据稀缺且昂贵，是唯一能拍板"晋级/回滚"的判据**。
3. **历史上有大量已付学费的知识没有防重机制**：ml/ 目录（监督学习 v0 + REINFORCE-lite
   S4 + rl1-rl5 对抗）整套被删（rl1-5 对 heuristicA 全 -4~-6/场），SpeedB/F/G 分支清理，
   正式赛 rank 87/205 教训（0 胡拖累 + 修复后场均 +2.4）……这些负面知识散落在
   PROJECT.md/git 注释/日志里，Agent 换一轮就可能重走。

**结论**：自迭代 = 「候选队列 → L1 离线门禁（快、便宜、筛掉 90%）→ L2 真机同桌门禁
（慢、贵、唯一裁决）→ 晋级/回滚 + 知识沉淀」的可重复闭环。评估口径与统计判据是
协议的核心，防重知识库是协议的保险丝。

## 2. 总体架构（双环）

```
                    ┌──────────────────────────────────────────────┐
  输入源             │              Agent 自迭代循环                 │
 ┌──────────┐   ┌───▼────┐   ┌──────────┐   ┌───────────┐   ┌──────▼───────┐
 │docs/iter │   │ 调度器  │──►│ L1 离线门禁 │──►│ L2 真机同桌 │──►│ 晋级/回滚    │
 │/queue.md │   │(主Agent)│   │ 分钟~小时 │   │ 数小时~日  │   │ + 知识沉淀    │
 │PROJECT.md│   └───┬────┘   └────┬─────┘   └─────┬─────┘   └──────┬───────┘
 │§7 候选池  │       │            │ 筛除/挂起       │              │
 │复盘/审计  │       │            └───────► 负结果登记（防重） ◄──────┘
 │真机事故   │       └────────────────── 报告卡 docs/iter/reports/ ──────┘
 └──────────┘
 资源: 本机 CPU 计时         资源: HM_PORTAL_COOKIE（短命, 人工补充）
       var/arena 数据         4×run_bot + keep_alive 看门狗
```

角色分工（多 Agent 形态随队列深度升级）：
- **调度器/主 Agent**：维护队列与优先级、派单、收集报告卡、裁决晋级、更新文档；
- **实现 Agent**（每候选一个）：写策略子类 + 单测，改动面最小化；
- **验证 Agent**：跑 L1 全部门禁并产出统计结论（不参与代码改动，避免自证）；
- **评审 Agent**（可选，晋级前）：code review 把关；
- **人工评审点**（不可省略）：L2 上真机前确认 cookie/资源、晋级合入时确认默认策略切换。

## 3. 候选队列与假设卡

每个候选在 docs/iter/queue.md 登记一张假设卡，字段固定：

```yaml
id: C001                        # 连续编号（speedx1 / x2 / …）
source: PROJECT.md §7.1 | 复盘审计差异#2 | 真机事故 | 新假设
domain: strategy | engine | protocol | eval      # 改动域（见 §5 门禁义务）
hypothesis: 一句话可证伪假设（含对照基准与预期方向）
change: 最小改动描述（文件级）
effect: 预期效应 δ（场分/局），判据需 δ 与 N 匹配（§6 公式）
cost: L1 估算 / L2 资源占用估算
status: queued | in-l1 | in-l2 | merged | rejected | dead-end | paused
depends: []                      # 依赖的基建改动
```

约束：
- **一个候选只动一件事**（改变量单一），否则判定结果无法归因；
- 候选一律实现为**新策略子类 + arena STRATEGIES 新名字**（如 speedx1），禁止改动
  SpeedE 本体与默认路径——A/B 对照才有意义，回滚只需删子类；
- 实验名用 `speedxN`（N 递增），**晋级后才给正式字母名**（如 speedH）并入竞技线；
- 每轮从队列取 cost 最低、δ×成功率期望最高的候选执行（打分：价值/成本，见 §8）。

## 4. L1 离线门禁（默认对每个候选强制执行）

顺序执行，任一 FAIL 即判负（仍登记报告卡）：

```powershell
# ① 回归：全量测试（含黄金集）+ 稳定性矩阵（0 违规/守恒）
python -m unittest discover -s tests
python tools/stability.py --strategy <xN>        # 新增变体必测

# ② 定向单测：新变体行为断言（差异点必须有测试钉住）
python -m unittest tests.test_speedx1

# ③ 同桌面 A/B：候选×2 vs SpeedE×2，8 巡，≥400 局（同一批内座位随机）
python -m arena.runner --combo "speedxNx2+speedEx2" --games 400 --rounds 8 --seed <S>
python tools/ab_gate.py --combo "speedxNx2+speedEx2"   # 判定输出（§6）
```

补充规则：
- 评估口径与参赛口径一致：**短局校准** `sim.WALL_RESERVE=60`（真机局 ~5-6 巡；
  PROJECT.md §7.4 已证明此口径影响结论）。默认口径表记录在 queue.md 头部；
- L1 用 ≥3 个不同 seed 分批跑（每批 200-400 局），以批为样本单元计算 delta 与 CI，
  避免单批种子偏差（ab_gate 支持 --recent 取最近批聚合）；
- 有引擎/协议侧连带改动的候选，先单独过引擎黄金集与协议测试。

**L1 判定输出（ab_gate 字段）**：N（同桌局数/席位）、delta（候选−基准，场均）、
delta 95% CI、判据结论：`WIN（CI 下界>0 且 delta≥δ_min）/ DRAW（含 0，不可分）/
LOSE（CI 上界<0）`。
- `LOSE/DRAW` → 直接登记 dead-end（**不升 L2**；真机资源稀缺，只送值得送的候选）；
- `WIN 且 delta≥δ_min`（δ_min 默认 2.0 场分/局，见 §6）→ 进入 L2。

## 5. L2 真机同桌门禁（唯一裁决，需人工提供 cookie）

前置条件：`HM_PORTAL_COOKIE=majiang_sid=...`（会话短命，由用户在过期后重新提供；
值暂存 var/.portal_cookie，已 gitignore，进程内注入环境变量使用）。

```powershell
# ① 建房得 4 令牌（M=1 房 = 四令牌真同桌无 AI；每用户 1 活动房，用完 close 释放）
python tools/room_ctl.py create --m 1 --rounds 8 --name "xN-vs-E"

# ② 同桌 ×4 进程：候选×2 + SpeedE×2（朱雀/玄武/白虎/青龙 命名惯例）
#    每进程配独立 --log logs/g<回合>_<方>.log；keep_alive 看门狗托管自动重启
python run_bot.py <tok1> --strategy speedxN --log logs/l2_xN_青龙.log
python run_bot.py <tok2> --strategy speedxN --log logs/l2_xN_白虎.log
python run_bot.py <tok3> --strategy speedE --log logs/l2_E_朱雀.log
python run_bot.py <tok4> --strategy speedE --log logs/l2_E_玄武.log

# ③ 提取场分：房自然结束后 room_ctl list / 房复盘 JSON（var/replays 下载）
#    口径：同桌 ≥200 局 或 房配置回合跑满；只统计候选与 E 双方均未 409/超时的有效局
# ④ close 释放房间
python tools/room_ctl.py close <room_id>
```

L2 判据与 L1 相同公式（§6），但**同桌配对性更强**，且需覆盖 ≥2 个独立房间
（跨时段/跨牌山批次）才能排除偶然。时长预算：真机局速受服务器节奏约束，
200+ 局通常数小时——**L2 挂后台 job 跑，期间不阻塞队列中其他候选的 L1**。

**L2 后裁决**：
- `WIN 且 delta≥δ_min` 且跨房可复现 → 晋级：正式字母名、入 run_bot STRATEGY_FACTORIES、
  更新 PROJECT.md §4 演进史、保留或清理实验分支；
- `DRAW`（如 E vs F 的 408 局先例）→ 登记 **converged**（平台收敛），不保留分支；
- `LOSE` → dead-end 登记。

## 6. 统计判据（唯一口径，禁止凭感觉）

沿用 PROJECT.md §6 推导：单局分标准差 σ≈10 → 场分差 δ 判定的最小局数
**N > (2/δ)² × 100**（δ=期望差/场）：

| 期望差 δ/场 | 需同桌局数 N | 本地 A/B 用时(8巡) | 真机同桌用时(估) |
|---|---|---|---|
| 4.0 | 100 | ~15 min | ~2 h |
| 2.0 | 400 | ~60 min | ~6-8 h |
| 1.0 | 1600 | 不划算 | 不划算（放弃该量级） |

- δ_min=2.0/场 是**晋级硬门槛**（小于此量级改进在真机不可判，历史 E/F 即前车）；
- 本地 L1 判据可用 δ≥2 且 CI 下界>0；**即便 L1 delta 很大也不直升竞技基准**
  （真机≠sim，SpeedB/E 的先例）；但 L1 delta<0 可一票否决（真机不太可能反转大负差）；
- 报告一律给「delta + 95% CI + N + 是否含 0」，不写"看起来更强"。

## 7. 知识沉淀与防重（防止换一轮重走学费）

- **docs/iter/queue.md**：候选队列 + 全部假设卡状态；
- **docs/iter/journal.md**：轮次流水（哪一轮跑了什么、结论、耗时、决策人）；
- **docs/iter/reports/<C00N>.md**：报告卡模板——
  假设 / 改动 diff / L1 证据（命令、N、delta、CI）/ L2 证据（房间、局数、delta、CI）/
  裁决 / 教训（为什么赢/输，给后续候选的启发）；
- **PROJECT.md**：演进史（§4）、真机事故清单（§5）、候选突破方向（§7）随晋级/负结果
  实时更新——这就是跨轮记忆；git 提交粒度 = 每候选一轮。
- **dead-end 登记即查重**：新候选入队前先 grep queue.md 与演进史，同一假设不得重复提交
  （E/F 不可分、rl 线全负、SpeedB 已退役是三类已交学费）。

停止扩张，输出总结论报告并回到人工评审（可能该换评估口径、换对手模型、或动协议域）。

## 9. 硬性护栏（Agent 行为红线）

1. **不碰竞技默认路径**：SpeedE/run_bot 默认策略在本方案迭代中只允许被"晋级动作"修改；
2. **协议域改动必须真机冒烟**（room_ctl + 1 桌短局）后才可谈合入；engine 改动必须
   黄金集全绿 + fan-calc 对拍（--smoke）；
3. **L2 房间是稀缺共享资源**：建房即计时，跑完立刻 close；进程崩溃由 keep_alive 托管，
   不许盲目无限重试（404 超 2min、409 风暴即停，遵循 game.py 现有守卫语义）；
4. **正式赛事参赛只走人工通道**（用户给参赛令牌才跑；Agent 不主动报名）；
5. **数据只增不删**：var/arena、var/replays、logs/ 是证据链，清理需人工确认；
6. **报告卡缺证据 = 该轮不成立**：每个"结论"必须可回溯到命令输出（N/delta/CI）；
7. **cookie/凭据**：HM_PORTAL_COOKIE 短命，过期即把 L2 候选挂起（不阻塞其他 L1），
   并在轮末消息中向用户请求新 cookie；连续 3 轮无 cookie 而 L2 候选积压时才记为阻塞。
