# 设计：正式赛为尺的基础策略迭代（SpeedE vs SpeedH 同赛段 A/B）

> 日期：2026-09-07 | 状态：待用户评审 | 配套：docs/iter/ 既有协议（本设计为其"窗口模式"修订版）

## 1. 背景与目标

用户指令（2026-09-06）：需要**更强的模型** + **比赛时不出问题**；本地 sim 不再作为
强度判据（四代候选已证明本地衰减偏差 >2/场）；"基础策略还没到最好"。

本设计确立新的迭代模型：
- **尺子 = 正式赛成绩**（历史基线：rank 87/205、修复后场均 +2.4，即 SpeedE 现状）；
- **裁决 = 同赛段 A/B**：每个正式赛窗口同时跑 基准 SpeedE 席位 + 新模型席位，
  对手相同（真人/混合），直接比场分——不再依赖 sim 自对弈预测强度；
- **sim 退役为回归工具**：仅用于 81 项测试/stability/决策合法性冒烟，不再产出强度结论；
- **首棒候选 SpeedH**：规则内"杠/链 EV"缺口（见 §4）——当前代码"可胡即胡、
  自杠一律不做"，在自摸-only + 杠/财飘 chain ×2 的规则下是明确的理论 EV 缺口。

## 2. 成功标准与判定协议

| 项 | 规则 |
|---|---|
| 主指标 | 同赛段内 SpeedH 席位 vs SpeedE 席位的场均分差 δ（同桌配对差，l2 口径 σ≈11 真机实测） |
| 次指标 | 窗口名次（与历史 rank 对比，仅参考——赛段对手构成可变） |
| 晋级线 | 两段式：快筛 n≈40-60（δ<-1.0 枪毙；≤+0.5 停跑）→ 终裁累计 n≈150 且 δ≥2.0/场 且 95%CI 排除 0（同 window_audit 判定） |
| 作废条件 | 席位异常率超阈值（见 §5）→ 该窗口数据作废重测 |
| 合入动作 | 晋级后：SpeedH 更名入竞技线 → run_bot 默认切换 → 演进史更新；每窗口只测 1 个候选版本（单变量纪律） |

有效场次定义：该场 gid 在 基准与候选 双方日志均完整（无 409 风暴/断线/超时代打），
同 l2_audit 的 incomplete 剔除逻辑。

## 3. 窗口运营协议（数据流与工具）

```
窗口前（开赛前 ≥30min）
  1. preflight READY + 81 测试全绿 + 新候选决策合法性冒烟（测试房 1 房短局）
  2. 席位分配：K 席 SpeedE + K 席 SpeedH（K≥1；建议 2+2，耗令牌但同赛段对照更稳）
  3. 每席独立 run_bot --log logs/w<序号>_<席名>.log，keep_alive 看门狗托管
窗口期
  4. 无人工：看门狗自动重启；异常 409/502 由 game/protocol 自愈
窗口后
  5. tools/window_audit.py（新，l2_audit 推广到任意 N 日志）：按 gid 跨日志配对
     还原每场各席分 → δ/CI/裁决 + 席位异常率报告（完成率/409 数/重启数）
  6. tools/replay_fetch.py（新，重建被删的拉取能力）：拉本窗口全桌复盘入库
     var/replays/<tid>/ → 供逐手审计（差异清单 → 下一候选假设源）
```

同赛段 A/B 注意事项：正式赛席位由服务器分桌，SpeedE/SpeedH 席位可能不在同桌
→ 配对差按"同赛段、同阶段、同房间（同 M 场次批次）"聚合：以场次 gid 所在
tournament/board 为块，块内两策略席位都出现才计入（window_audit 实现块级配对）。

## 4. 首棒候选 SpeedH：杠/链 EV（v1 范围：杠决策；胡决策不动）

### 4.0 事实缺口（设计前提，必须先行探明）

- sim 代码（v2）自杠后**不补牌**，与其文档"杠→补牌→杠上花/连杠路径"矛盾
  → sim 无法建模杠 EV，SpeedH 的合法性/收益语义必须以**真机为准**；
- 真机协议是否接受 draw 回合提交 gang（暗杠/补杠）动作、杠后补牌/连杠/杠上花
  的确切事件序列、chain×2 倍率在结算中的口径——当前 bot 代码从未走过该路径。

### 4.1 P0：真机规则语义探针（测试房，不依赖窗口）

用 room_ctl 建房 + 特制探针策略（bot/speedprobe.py，仅测试房用）强制触发：
1. 暗杠（自摸 4 张同码，白板除外）→ 记录服务器事件序列（补牌？连杠窗口？）；
2. 补杠（碰组 + 第 4 张）→ 同上；
3. 杠上花（杠后补牌即胡）→ 番数与 chain 倍率核对（对照 fan-calc 黄金集口径）；
4. 过胡合法性：胡形在手但提交 discard → 服务器 409 还是放行？（决定打点候选可行性）
5. 结算中杠 chain 对场分的影响（对照本场积分）。
产出：P0 探针报告（事件序列/合法性矩阵/倍率核对表）→ 决定 v1 实现面。

### 4.2 P1：SpeedH 实现（基于 P0 结论的最小 EV 门控）

- 恢复"自杠"路径（game/decide 支持 draw 回合 gang 提交，仅当 view 显示可杠）；
- 门控原则（EV 保守版）：
  * 补杠：已有碰组 + 第 4 张 ∈ 手牌 且 不破坏已听/胡结构（杠后 13 张仍听或
    补牌可胡）→ 杠（chain+1 ×2 期望为正且无结构代价）；
  * 暗杠：4 张同码 + 杠后形态仍 ≥ 当前向听 → 杠（白板禁杠规则遵守）；
  * 自杠一律不做 的旧保守逻辑替换为上述门控；
- v1 明确不做：过胡等更高番、财飘主动化、弃白战术——留 v2+（等 P0 探针 4 结论）；
- 回归义务：81 测试全绿 + stability ALL PASS + 测试房短局冒烟（0 违规/409 风暴）。

### 4.3 P2：窗口 A/B 与裁决

按 §2/§3 执行；候选版本锁定（窗口内 SpeedH 代码冻结，只允许日志/托管层热修）。

## 5. 稳定性保障（用户硬要求"比赛不会出问题"）

| 层 | 机制 | 验收门槛 |
|---|---|---|
| 事前 | preflight + 81 tests + 候选短局冒烟（含 SpeedH 新路径） | READY，全绿 |
| 事中 | keep_alive 看门狗（已有）+ guide 版本自检（已有）+ 409/502 自愈（已有） | 场次完成率 ≥95% |
| 事后 | window_audit 席位健康报告（重启次数/409 计数/超时代打/断线场次） | 异常场次 <5%，否则该窗口作废 |
| 版本闸 | 指南 BREAKING 检测（smoke 已带）；窗口前人工确认无 BREAKING | 有 BREAKING → 停赛核对 |
| 回滚 | SpeedE 席位全程保留 → 任何异常都可回到纯 SpeedE 状态（run_bot 默认不动） | — |

## 7. 风险与边界

- 窗口节奏不可控：可能数天无窗口 → P0/P1 期间无阻塞（探针用测试房即可）；
- 令牌供给：每窗口需 2K 令牌（用户提供）；K=2 建议，最小 K=1 也可判但更慢；
- 同赛段分桌偏差：跨桌对手强度差异会放大噪声 → 块级配对 + n≥200 对冲；
- sim 退役边界：强度判据不用 sim，但**决策合法性冒烟**仍走 stability/tests（sim 内核）；
- 打点/过胡候选依赖 P0 探针 4 的合法性结论，探明前不做。
