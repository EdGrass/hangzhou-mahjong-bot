## 3. 路线 A 的具体设计（可直接开工）

**目标**：让「同一向听下选哪条路」由**前瞻预测**决定，而不是手写偏好（后者已 5 次失败）。

1. `mahjong/rollout.py`（新文件，不动现有引擎）：
   - 输入：14 张手牌 + 公开信息（副露/河/白用量）
   - `score_discard(d)`：对每个候选弃牌，用**真实剩余牌墙分布**做 N 次随机采样，
     每次按现有 `_best_discard_t` 走 k 步（k=2..3），返回
     `P(k 步内听牌)` 与 `E[番数 | 胡]` 的估计；
   - 混合目标：`EV = P(听) × E[番]`（与真机得分代理同构，已验证 r=0.95）。
2. 缓存：同一手牌+同一公开信息 → 结果缓存（LRU 20万），决策预算 ≤ 200ms。
3. **只在关键局面启用**（向听 ≤2 或候选间代理差 <5%），其余仍走 speedtug（保证不退化）。
4. 门禁（必须全过才送真机）：
   - sim 3 seed × 192 局：代理 ≥ 0.422（不退）、听牌率不退、违规 0；
   - 决策延迟 P99 < 500ms（真机 1s 窗口）；
   - 真机 3 房 A/B（match_super --strategy scoretu）对比 speedtug。

## 5. 实测结果（2026-09-11 02:00，方案A 朴素版 = 已否证）

| 变体 | 目标 | 代理 |
|---|---|---|
| 基线 SpeedTUG | — | **0.422** |
| V1 | P(听牌)，k=2 | 0.266 |
| V1b（修向听计算顺序） | P(听牌)，k=2 | 0.344 |
| V1c（候选按基线同键） | P(听牌)，k=2 | 0.281 |
| V3 | **P(胡牌)，k=3** | 0.297 |

**失败机制（重要）**：听牌率能维持（64.1% vs 67.2%），但**胡率从 29.7% 崩到 18.8~21.9%**。
即 rollout 只关心「到达听牌」，不关心「听形能不能胡」——自摸制下必须真摸到那张，
等待宽度/番数/副露/对手全都没进目标函数。耗时 8s/局（基线 0.8s/局）。

**可工作的版本必须**（任一缺失都会重蹈覆辙）：
1. 目标 = `P(胡) × E[番]`（含爆头 ×2 与链），不是 P(听牌)；
2. 状态里含副露与「爆头潜力」（否则建模不到门清/副露两条爆头路线）；
3. 等待宽度质量（剩余活张）作为特征或直接进 rollout 的胜负判定；
4. 性能：真机 1s 窗口 → 需缓存/蒸馏（当前朴素版 8s/局，慢 10 倍）。
