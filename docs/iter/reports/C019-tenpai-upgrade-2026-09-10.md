## 2. 排除项（用数据排除，不猜）

- **死听**：首次听牌时按「4 − 四家手牌 − 副露」算真·剩余张数
  （`var/_deadwait.py`）→ 死听局占比 **我方 0.0% vs 冠军 0.1-0.3%**；活等副本
  7.47 vs 8.91。**不是死听、也不是宽度碾压**。
- **听牌速度**：均听巡 6.43 vs 6.26-6.74，持平。
- **引擎能力**：`var/_baotou_engine.py` 自检——e=3 副露 + 暗手
  `[1w,2w,3w,白]` → `shanten=0 / waits=34 / is_baotou=True`；且 5 张局面下
  `_best_discard_t` 正确地弃出万能听（34 张）而非窄听。**评估与判定都正确。**

## 3. 真因：自己的「已听不副露」把爆头路线堵死

推导（关键，且与自摸和规则耦合）：

1. 爆头态 = 4 面子（含副露）+ **白孤**，13-3e-g 张；
2. 因**自摸和**，副露到 e=3 后那手 5 张「1 面子 + 白 + X」虽已成胡形，
   **不能胡**（非自摸），只能弃牌 → 弃 X 恰好落进「1 面子 + 白孤」= **爆头**；
3. 而 e=2 时那手 7 张（含对子+白）**已经 shanten 0**；
4. SpeedE/M/TM 的窗口判据一律是「已听（before<=0）不副露」→ **亲手拒掉了
   那次把 e→3、进而拿到 34 张万能听 + ×2 番的副露**。

即：**副露独有的「换听升级」窗口被自己的保守判据关掉了。**

## 4. 修复：C019 / SpeedTU

`bot/speedtu.py` —— 与 SpeedTM 的唯一差异 = 已听状态下的窗口判据：

```
before > 0  → 沿用 TM mild（after <= before 即接受）
before == 0 → 仅当【副露 + 最优弃牌】后仍是听牌且等待张数严格变多才接受
              （爆头 34 张必然通过）
```

其余 100% 继承（出牌 = SpeedT；吃 ≤2 摊自限、抓打圈、胡 = SpeedE）。
