## 3. 两条闸门（可直接粘进下一役预登记）

### 3.1 判决资格闸门
> 一个臂只有在**窗口内并行基线覆盖 ≥ 60%**（基线房数 ÷ 候选房数）时才允许出"采用 / 判负"结论；
> 否则只能记 **"未判定（功效不足）"**，并且**不得**用"全史均值 / 别时段均值"当对照。
> 依据：R757 体检 16 个臂，**6 个覆盖 <60%**（`c211`/`c073w2`/`c068lo0`/`speedtu`/`c118` 全为 **0%**），
> 而 `c193/c194/c146/c191` 的并行差分 z = +0.13/−0.21/+0.52/−0.27 ⇒ **全是零，不是"证明无效"**。

### 3.2-a **禁止单臂战役**（★ 主闸门，真正能拦住 c211 的那一条）
> **任何候选臂开跑，基线臂必须同时在跑**；战役期间若出现"某臂在跑、基线 0 房"的窗口
> ⇒ **该窗口的房不计入该臂的任何判据**，且该臂状态只能记 **"未判定"**。

- **依据（这是 c211 那 101 房的真正教训）**：c211 窗口内并行基线 = **0 房**，
  而当时的**灾难熔断**（6 房/−300）与**慢漏止损**（下条）都**不触发** —— 两条都拦不住它。
  唯一能拦住的是"**根本没有并行基线就不许出结论**"。
- 实现：`var/_verdict_validity.py`（覆盖率体检，退出码非 0 即违规）。

### 3.2-b 慢漏止损条款（次要保险；**如实标注其历史命中率**）
> **灾难熔断**（沿用）：6 房内累计 ≤ −300 ⇒ 立刻停该臂。
> **慢漏止损**（新增）：从第 8 房起，每次排批后算**单侧检验**
> `z = (候选累计均值 − 同时段基线累计均值) / SE`（Welch）；
> **连续两次检查 z ≤ −1.645** ⇒ 停该臂，记"判负（慢漏）"。
> 工具：`python -X utf8 var/_harm_guard.py`（实时看护）、`var/_harm_backtest.py`（历史回放）。

⚠ **如实报告回测结果（2026-09-21 更正）**：用**与看护一字不差**的规则（战役窗口内因果基线 + 连续两次）
回放 16 个历史臂，**只有 1 次触发**（`speedtug` 在第 28 房，省 **+299 原始分**），
**不会**拦住 `c193/c194/c135/c211` 任何一个。
⇒ **不要把这条当成主要防线**；它的价值是"以后万一出现缓慢恶化时的兜底"，**不是**解决 c211 问题的工具。

## 4. 设计建议：下一役用**三臂**，效率高 33%

同样的总房数 R、单房 SD=s：
- **两臂**：每臂 R/2 房 ⇒ 对比 SE = s·√(4/R)
- **三臂**（基线 + 两个候选）：每臂 R/3 房 ⇒ 对比 SE = s·√(6/R) ⇒ **CI 宽 1.22 倍，需 1.5 倍房数才能达到同样精度**
- 但**三臂一次给出 2 个候选对比** ⇒ 单位时间的信息量 = 2 / 1.5 = **1.33 倍**

⇒ **在"候选多、时间少"（我们有 ~27 天 ≈ 8 个两臂战役的预算）的现状下，三臂是更优的默认。**
（本役前身 `arms=speedtugc/speedc151/speedc191` 已经这样跑过一次，链路可用。）
