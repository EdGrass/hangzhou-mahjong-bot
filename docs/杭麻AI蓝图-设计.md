## 1. 目标与总路线

**总目标**：从"协议正确但无牌技"（naive）推进到"能在真实锦标赛稳定赢分"（启发式
基线），并落地一条到"杭麻版 Mortal"（小策略网络 + Arena 自对弈数据工厂）的可执行路径。

**设计洞察（只自摸）**：杭麻只允许自摸胡 → 无荣和防守/读弃牌博弈，模型要学的核心是
效率竞速 + 番型取舍 + 牌山/副露窗口管理，策略空间小于日麻 → 模拟自对弈学习更易收敛。
2 传统算法 + 2 模型**混编一桌**（恰好 4 座）：
- 模型永远面对 2 个确定性基线对手 → 防纯自对弈漂移，形成持续评估门；
- 每局同时产出 事件流（全手牌）+ 结局（得分/名次）→ **对局即数据**；
- 版本/座位轮换 → 数据多样性 + 无偏评估。

## 3. 里程碑与验收门

### M1 — 权威规则引擎 + 模拟器 v0 + 启发式基线（先行）
交付：
- `mahjong/` 纯算法包：牌型/向听数/听牌/胡牌判定/番型/爆头/七对（含财神百搭、
  副露、吃≤2、杠语义），与 `fan-calc` 逐例对齐（单测批量比对）；
- 本地对局推进器（发牌/摸打/副露窗口/流局/连庄/结算）——**模拟器 v0**；
- 启发式策略 A（首版 `Strategy` 实现）：出牌 = 向听数贪心 + 搭子价值 + 财神处理
  + 爆头态特判（可弃胡飘 ×4 起）；窗口收益判定后吃/碰/明杠；可自摸即胡；
- 动作合法性掩码接口（引擎输出，供真机自检与未来模型使用）。

验收门：
- 引擎与 fan-calc ≥200 随机组合 100% 一致（含爆头/七对/4 白板）；
- 本地模拟 4 AI（3 启发式 A + 1 naive）500 局：启发式显著优于 naive，
  无死锁；模拟器自检 0 次非法动作；
- 单局模拟速度基线（纯 Python）≥ 若干局/s，作为 Arena 吞吐参照。

### M2 — 评估闭环（本地跑分器）
- 跑分器：N 局自对弈 → 平均顺位/胜率/胡率/均番/流局率 + 置信区间；
- 基线池：naive / 随机 / 启发式 A（各版本存档）；改一版策略 ≤1h 出统计结论；
- 真机事件流回拉器（测试房间/已结束锦标赛 → 离线复盘我方决策）。

验收门：M1 之后任何策略改动都能快速给出与基线对比的统计结论。

### M2.5 — 本地 Arena 数据工厂 v0（纯传统算法先行验证）
- 调度器：任意 4 策略混编一桌（席位/版本轮换），批量连续对局；
- 数据落盘：JSONL（全事件流 + 结局 + 元数据），**对局即数据**；
- 吞吐优化：先 4 传统算法自对弈验证吞吐与数据量（目标 ≥100 局/min 起步，
  瓶颈定位后 numpy/向量化/多进程加速）；
- 版本注册表：模型/策略存档、对手池配置（2 固定基线 + 可换对手）。

验收门：Arena 吞吐达目标、数据落盘完整可回放、跑分与 M2 跑分器口径一致。

### M3 — 学习线 v0：教师 + 监督蒸馏（M1 落地后启动）
- 教师：受限 MCTS（≤3s/局面预算）与启发式 A 在 Arena/跑分局面上生成
  (局面, 动作分布/标签)；
- 小策略网 v0：policy+value 双头（1–10M 参），PyTorch，GPU 训练；
- 特征/动作空间见 §5；动作掩码由引擎给定；
- 数据规模目标：监督预训练 ≥10 万局面起步（视吞吐与 GPU 扩）；
- 验收门：本地跑分 vs 启发式 A（平均顺位显著提升、合法率 100%）。

### M4 — Arena RL / 自对弈迭代（v0 之后，go/no-go）
- 2 传统 + 2 模型混编进入 RL 微调（奖励 = 得分与名次）；对手池渐进
  （祖先 → 启发式池 → 最新版）；平台回放/LLM 教师作为增强项单独立项。

## 4. 杭麻语义 → 模拟器必须逐条实现（正确性清单）

1. 136 张（万筒条 1-9 ×4 + 东南西北中发白 ×4），白板 = 财神（百搭）；
2. 财神不可被吃/碰/杠/胡（作为财神本身），可主动打出；
3. 抓打圈：打出财神后一圈，别家不能吃/碰/明杠（可暗杠/自摸胡），
   出牌只能打刚摸的牌；
4. 只自摸、禁抢杠胡；吃 ≤2 摊，碰/杠不限；碰(含明杠)窗口先于吃窗口；
5. 最后 10 墩（20 张）保留不摸、最后 10 墩内禁杠；摸完无人胡流局，流局庄家连庄；
6. 连庄 ×8 直上三连庄（首局即 ×8），闲 ×1；
7. 胡形：4 面子+将 或 七对（含豪华/双/三豪华、4 真白板当刻）；爆头（听牌态摸
   任意 1 张即胡）；正好 4 白板不算爆头；副露后与七对/杠互斥（2026-09-02 口径）；
8. 动作链：飘/杠每动作 ×2，可组合连续（杠开=杠上花 ×2 含在内），断链清零；
   财飘 = 爆头态打白板；
9. 番型连乘：分支 × 2^链 ×（4 白板 ×2）×（爆头 ×2），全局最大 ×512；
10. 结算：底分 × 番 ×（庄 8/闲 1），三家分别结算；
11. "弃胡/飘"必须是合法且有价值的动作（爆头摸白可 hu 或弃胡飘），训练可见。

> 校验手段：fan-calc 批量比对 + 事件流 API 回放比对（对局推进）。

## 5. 特征与动作空间（学习线草案）

观测（定长张量，单玩家视角）：手牌 34 计数（含摸牌标志）、副露组、四家弃牌
（34×4，含抓打圈标志）、财神数、庄位、局数、墙剩、各分数、爆头态、chain_count、
我方可行动作掩码（引擎实时给出）。
动作（按阶段给集合）：draw 态 = 切 34 + 杠（暗杠/补杠按牌）+ hu；窗口态 =
吃（含两张手牌选择）/碰/明杠/过；抓打圈只许切刚摸的牌（掩码强制）。

## 6. 本地训练面板（FastAPI，R7）

- 形态：`localhost` 单机 Web（默认 http://localhost:8088），只读监控起步；
  运行控制（启停/版本快照/对手池配置）二期再加；
- 数据通道：训练/Arena 进程只写 指标 JSON 快照 + JSONL 样本/战绩库，
  面板进程只读——**进程解耦**，任一方崩溃不影响另一方；
- 页面区块：
  | 区块 | 内容 |
  |---|---|
  | 总览 | 训练轮次/样本库计数/Arena 吞吐(局/s)/当前版本 |
  | Arena 战报 | 各版本 vs 传统 A/B 的胜率/平均顺位/胡率 + CI，趋势图 |
  | 曲线 | 监督 loss、胜率随版本、番型分布 |
  | 对局回放 | 最近 N 局逐手（牌型/决策/动作链），事件流存档回放 |
  | 控制（二期） | 启停/版本快照/对手池配置 |
- 依赖：FastAPI + uvicorn（面板独立于 bot 纯标准库部分，venv 隔离）。

## 7. 关键技术决策

- D1 模拟器语义：按 §4 全量实现；先纯 Python（正确性优先），吞吐不足时
  numpy 向量化 → C/GPU 批处理；
- D2 动作合法性：引擎掩码，不让网络自悟财神规则；
- D3 教师：(a) MCTS+启发式（已选）→ v0 监督标签；(b) 平台回放监督：需先探测
  门户数据权限；(c) LLM 教师：小众语义判定质量需小规模人工抽验后再立项；
- D4 网络：小 transformer/MLP 级策略网（参考日麻 Mortal 量级 1–10M 参），
  policy+value 双头；ONNX 固化推理；
- D5 训练：v0 监督蒸馏 → M4 Arena RL；奖励 = 得分与名次；
- D6 评估门：5000+ 局统计口径，防单局噪声；2 传统算法始终在场当固定基线；
- D7 Arena 吞吐目标：纯 Python ≥100 局/min 起步 → 优化后 ≥1000 局/min。
