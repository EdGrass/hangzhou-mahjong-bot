# 杭麻 AI 蓝图：启发式基线 → Mortal 式学习线（设计文档）

> 日期：2026-09-03 ｜ 状态：已确认方向，待 M1 开工
> 范围：本仓库（D:\hangzhouMaj）杭州麻将 bot 的牌技路线总设计。
> 背景协议：接入指南 v8（多阶段锦标赛 / 财神规则 / 只自摸 / 动作链番型）。

## 1. 目标与总路线

**总目标**：把 bot 从"协议正确但无牌技"（naive）推进到"能在真实锦标赛与测试房间
稳定赢分"（启发式基线），并保留一条到"杭麻版 Mortal"（小策略网络 + 自对弈/蒸馏）
的可执行路径。

**两条线、一个内核**：

```
                 ┌──────────── 内核（一次建设，两线共用）────────────┐
  平台事件流API    │  权威规则引擎 = 本地快速模拟器：                   │
  fan-calc API ──▶│  136牌/财神(白板)全语义/爆头/七对/飘杠链/庄×8/结算  │
  校验/真值 ─────▶│  可自对弈、可跑分、可造训练样本、可推演（规则前向） │
                 └───────────────┬────────────────────────────────────┘
    M1/M2 启发式线                │              M3/M4 学习线（后期）
  启发式策略（向听/效率/财神/   ◀─┘──▶ 数据管道 → 小策略网 → MCTS教师
  安全牌）→ 测试房间实盘/本地跑分            → 自对弈微调 → 评估门上池
```

- 规则引擎（M1 产物）**就是**未来训练模拟器，不是过渡品；
- 学习线 v0 教师 = 本地受限 MCTS + M1 启发式（决策已确认，方案见 §6 D3）；
- 推理嵌入现有 `Strategy` 接口，协议层（bot/game.py 等）零改动。

## 3. 里程碑与验收门

### M1 — 权威规则引擎 + 启发式基线（先行，1–2 天）
交付：
- `mahjong/` 纯算法包：牌型/向听数/听牌/胡牌判定/番型/爆头/七对（含财神百搭、
  副露、吃≤2、杠语义），与 `fan-calc` 逐例对齐（单测批量比对）；
- 本地对局推进器（发牌/摸打/副露窗口/流局/连庄/结算）——**模拟器 v0**；
- 启发式策略（M1 版 `Strategy`）：
  - 出牌：向听数贪心 + 搭子价值 + 财神保留/利用 + 爆头态特判（可弃胡飘 ×4 起）；
  - 窗口：收益判定后才吃/碰/明杠，否则过；
  - 胡：自摸即胡（首版）；弃胡仅出现在"飘/杠链可提升番型且局面安全"的窄分支；
- 协议层接入点验证（替换 NaiveStrategy 跑真实测试房间——令牌到位后）。

验收门：
- 引擎与 fan-calc 在 ≥200 随机手牌/番型组合上 100% 一致（含爆头/七对/4 白板）；
- 本地模拟 4 AI（3 启发式 + 1 naive）500 局：启发式胜率/胡率显著高于 naive，
  无死锁/无限局（流局率有界）；
- 动作合法性：自对弈日志中 409 INVALID_ACTION 次数为 0（模拟器内自检）。

### M2 — 评估闭环
- 本地跑分器：N 局自对弈 → 平均顺位/胜率/胡率/均番/流局率 + 置信区间；
- 真机事件流回拉器：测试房间/已结束锦标赛的完整对局 → 离线复现我方决策、
  按局统计（为 M3 数据管道铺路）；
- 基线池：naive / 随机 / M1（各版本存档，供学习线对手池与回归测试）。

验收门：改一版策略能在 ≤1 小时内给出与基线对比的统计结论。

### M3 — 学习线 v0：数据管道 + 监督蒸馏（M1 落地后启动）
- 训练环境：M1 模拟器加速版（numpy/向量化，必要时 C 扩展/GPU 批量环境）；
- 教师：受限 MCTS（默认浅推演 ≤3s/局面预算）在 M1/M2 产出局面上生成
  (局面, 动作分布/标签)；
- 小策略网 v0：policy+value 双头（1–10M 参，输入定长张量见 §5），
  PyTorch，GPU 训练；
- 评估门：本地跑分 vs M1 基线（平均顺位提升达显著水平且动作合法率 100%），
  过了才允许真机试跑。

### M4 — 自对弈迭代（可选，go/no-go 评估）
- PPO/类 AlphaZero 自对弈：奖励 = 场得分与名次（番型自然涌现）；
- 对手池渐进（祖先 → M1 池 → 最新版）；
- 平台回放/LLM 教师作为增强项单独立项评估（不阻塞主线）。

## 4. 杭麻语义 → 模拟器必须逐条实现（正确性清单）

1. 136 张（万筒条 1-9 ×4 + 东南西北中发白 ×4），白板 = 财神（百搭）；
2. 财神不可被吃/碰/杠/胡（作为财神本身），可主动打出；
3. 抓打圈：打出财神后一圈，别家不能吃/碰/明杠（可暗杠/自摸胡），
   出牌只能打刚摸的牌；
4. 只自摸、禁抢杠胡；吃 ≤2 摊，碰/杠不限；碰(含明杠)窗口先于吃窗口；
5. 最后 10 墩（20 张）保留不摸、最后 10 墩内禁杠；摸完无人胡流局，流局庄家连庄；
6. 连庄 ×8 直上三连庄（首局即 ×8），闲 ×1；
7. 胡形：4 面子+将 或 七对（含豪华/双/三豪华、4 真白板当刻）；
   爆头（听牌态摸任意 1 张即胡）；正好 4 白板不算爆头；
8. 动作链：飘/杠每动作 ×2，可组合连续（杠开=杠上花 ×2 含在内），
   断链（打出非飘非杠牌）清零；财飘 = 爆头态打白板；
9. 番型连乘：分支 × 2^链 ×（4 白板 ×2）×（爆头 ×2），全局最大 ×512；
10. 结算：底分 × 番 ×（庄 8/闲 1），三家分别结算；
11. 副露后七对互斥、杠与七对互斥（2026-09-02 修订口径）；
12. 训练样本里"弃胡/飘"必须作为合法且有价值的动作存在（爆头摸白可 hu 或弃胡飘）。

> 校验手段：fan-calc 批量比对（判定+番型+结算）+ 事件流 API 回放比对（对局推进）。

## 5. 特征与动作空间（学习线 v0 草案）

观测（定长张量，单玩家视角）：
- 手牌：34×1 计数（可另含摸牌标志）；副露组编码；
- 四家弃牌：34×4 计数/序位（含抓打圈标志）；
- 全局：财神数、庄位、局数、墙剩、各分数、爆头态、chain_count；
- 我方可行动作掩码（由规则引擎实时给出，模型只输出合法分布）。

动作（按阶段给集合）：
- draw 态：切 34 种；杠（暗杠/补杠按牌选）；hu；pass（不适用）；
- 窗口态：吃（含两张手牌选择组合）/碰/明杠/过；
- 特殊：抓打圈只许切刚摸的牌（掩码强制）。

## 6. 关键技术决策（含已选与备选）

- D1 模拟器语义：按 §4 全量实现，先纯 Python（正确性优先），
  自对弈吞吐不足时 numpy 向量化 → （预算内）C/GPU 批处理；
- D2 动作合法性：一律引擎掩码，不让网络自悟财神规则；
- D3 教师：(a) MCTS+启发式（已选）→ 产出 v0 监督标签；
  (b) 平台回放监督：需先探测门户数据权限（owner 登录态可拉 `/portal/api/games/{id}/events`）；
  (c) LLM 教师：对杭麻小众语义的判定质量需小规模人工抽验后再立项；
- D4 网络：小 transformer/MLP-Mixer 级策略网（参考日麻 Mortal 量级，
  1–10M 参），policy+value；ONNX 固化推理；
- D5 训练：v0 监督蒸馏 → M4 PPO/自对弈；奖励 = 得分与名次；
- D6 评估门：见各里程碑验收门；5000+ 局统计口径，防单局噪声。
